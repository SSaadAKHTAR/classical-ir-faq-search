EXTENSIVE CODE DOCUMENTATION - CLASSICAL IR FAQ SEARCH
=============================================================================

This document explains EVERY function in the project `main.py` in extreme detail. 
It covers Input, Logic, and Output for each method.

-----------------------------------------------------------------------------
1. CLASS SETUP & INITIALIZATION
-----------------------------------------------------------------------------

A. `__init__(self, k1=1.5, b=0.75)`
   - **Purpose**: Constructor. Sets up the empty state of the system when you start it.
   - **Parameters**:
     - `k1`: Controls BM25 term frequency saturation. (Default 1.5). Higher = matching words matter more.
     - `b`: Controls BM25 length normalization. (Default 0.75). Higher = penalize long sentences more.
   - **Key Variables Initialized**:
     - `self.documents`: Stores the raw text.
     - `self.word_index`: The "Inverted Index" (Map of Word -> Sentence IDs).
     - `self.idf`: The "Importance" scores for each word.
     - `self.stopwords`: List of boring words to ignore.

B. `_get_stopwords(self)`
   - **Purpose**: Returns a set of common words (like "the", "is", "at") that carry little meaning.
   - **Logic**: We filter these out during processing so the system focuses on "important" keywords (nouns/verbs).

-----------------------------------------------------------------------------
2. TEXT PROCESSING (The Foundation)
-----------------------------------------------------------------------------

C. `tokenize(self, text)`
   - **Purpose**: Splits a string into individual words (tokens).
   - **Logic**: 
     - Converts text to lowercase (so "The" and "the" match).
     - Uses Regex `\b[\w]+\b` to find word boundaries.
     - **Returns**: A list of strings (e.g., `["hello", "world"]`).

D. `preprocess(self, tokens)`
   - **Purpose**: Cleans up tokens to make matching easier.
   - **Logic**:
     1. Removes Stopwords (using the set from B).
     2. Removes short words (length <= 2).
     3. **Stemming**: Chops off suffixes (e.g., "running" -> "run", "berries" -> "berry"). This ensures "run" matches "running".
   - **Returns**: A list of "stemmed" keywords.

E. `split_into_sentences(self, text)`
   - **Purpose**: Breaks the document into sentences.
   - **Logic**: Uses Regex `[.!?]+\s+` to split wherever there is a period/exclamation/question mark followed by space.
   - **Why?**: Our answers are specific sentences. We need to index sentences, not just whole docs.

-----------------------------------------------------------------------------
3. INDEXING (Making it Searchable)
-----------------------------------------------------------------------------

F. `load_document(self, document_text)`
   - **Purpose**: The "Main" function for Phase 1. Orchestrates the whole indexing process.
   - **Flow**:
     1. Stores the document.
     2. Calls `split_into_sentences`.
     3. Calls `_build_inverted_index`.
     4. Calls `_calculate_idf` and `_build_tfidf_vectors`.
     5. Sets `self.document_loaded = True`.

G. `_build_inverted_index(self)`
   - **Purpose**: Creates the "Search Map".
   - **Logic**:
     - Loops through every sentence.
     - For every word in the sentence, adds the Sentence ID to `self.word_index`.
     - *Example Result*: `{ "computer": [0, 5, 12] }` -> "Computer appears in sentences 0, 5, and 12".

H. `_calculate_idf(self)`
   - **Purpose**: Calculates Inverse Document Frequency (Word Rarity).
   - **Formula**: `IDF = log( (Total Sentences + 1) / (Sentences with Word + 1) )`
   - **Meaning**: High IDF = Rare word (Important). Low IDF = Common word (Unimportant).

I. `_build_tfidf_vectors(self)`
   - **Purpose**: Pre-calculates the "Vector" for each sentence.
   - **Logic**:
     - Count frequency of words in sentence (TF).
     - Multiply by IDF.
     - Store the result `Reference Vector` to compare against user questions later.

-----------------------------------------------------------------------------
4. RETRIEVAL (Phase 1 of Q&A)
-----------------------------------------------------------------------------

J. `bm25_score(self, query_terms, doc_idx)`
   - **Purpose**: The math engine. Calculates a "Relevance Score" for ONE sentence against the question.
   - **Logic**: Implements the BM25 formula.
     - Increases score if sentence contains query terms.
     - Penalizes score if sentence is very long (Length Normalization).
     - Limits score increase if term appears too many times (Saturation).
   - **Returns**: A float number (Score).

K. `retrieve_passages(self, query, top_k=5)`
   - **Purpose**: Finds the Top 5 best sentences for a question.
   - **Flow**:
     1. Preprocesses the Question (Tokenize -> Keep Keywords).
     2. Loops through ALL sentences (0 to N).
     3. Calls `bm25_score` for each.
     4. Sorts by Score (Highest first).
     5. **Returns**: Top 5 sentences.

-----------------------------------------------------------------------------
5. READING & ANSWERING (Phase 2 of Q&A)
-----------------------------------------------------------------------------

L. `_classify_question_type(self, question)`
   - **Purpose**: Guesses what *kind* of answer the user wants.
   - **Logic**: Checks start of string.
     - Starts with "Who" -> Returns "who".
     - Starts with "When" -> Returns "when".
     - ...and so on.

M. `read_and_extract_answer(self, question, passages)`
   - **Purpose**: The "smart" part. Extracts the exact answer from the best passage.
   - **Logic**:
     1. Takes the #1 ranked sentence from Retrieval.
     2. Checks Question Type (from L).
     3. **Regex Pattern Matching**:
        - **Type 'definition' (What is?)**: Looks for pattern `Subject IS Description`.
        - **Type 'time' (When?)**: Looks for `\d{4}` (Year).
        - **Type 'number' (How many?)**: Looks for digits or number words ("one", "ten").
     4. **Returns**: Dictionary with `{'answer': "...", 'confidence': 0.9}`.

N. `answer_question(self, question)`
   - **Purpose**: The User-Facing wrapper.
   - **Flow**:
     `User Question` -> `retrieve_passages` -> `read_and_extract_answer` -> `Print Answer`.

-----------------------------------------------------------------------------
6. FAQ GENERATION
-----------------------------------------------------------------------------

O. `generate_faq(self, num_questions)`
   - **Purpose**: Auto-generates questions from the text.
   - **Logic**:
     1. Calculates a "Importance Score" for every sentence (Sum of TF-IDF weights).
     2. Boosts score if sentence contains "important", "main", "result".
     3. Picks top N sentences.
     4. Calls `_generate_question` to turn them into Q&A pairs.

P. `_generate_question(self, sentence)`
   - **Purpose**: Converts a statement into a question.
   - **Logic**:
     - *Definition Pattern*: If sentence matches "X is Y", returns "What is X?"
     - *Causal Pattern*: If sentence contains "because", returns "Why...?"
     - *Fallback*: If it looks like a proper Fact, returns "What can you tell me about [Subject]?"

-----------------------------------------------------------------------------
7. UI HELPER FUNCTIONS
-----------------------------------------------------------------------------

- `loading_animation`: Shows the `| / - \` spinner.
